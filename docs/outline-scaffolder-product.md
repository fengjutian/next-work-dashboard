# 章节生成器：独立产品文档

> 产品代号：Chapter Studio  
> 当前实现：`@next-work-dashboard/outline-scaffolder`  
> 文档状态：Draft 1.0  
> 适用对象：产品、设计、研发、测试、运营

## 1. 产品概述

章节生成器是一款面向长篇非虚构内容生产的 AI 写作工作台。它把“想法或目录”转化为一组结构化、可持续编辑、可审校并可发布的章节文档，解决长篇写作中目录难落地、章节边界模糊、材料与观点脱节、多人审校难追踪以及成稿质量不稳定的问题。

产品既可作为独立桌面应用运行，也可作为 React 能力包嵌入其他宿主。独立产品不依赖 Prompt Lab 的内部实现；文件系统、AI、密钥、检索、Git 和发布能力通过宿主适配器接入。

一句话定位：**从目录规划到出版交付，为长篇内容提供有证据约束的章节生产流水线。**

## 2. 目标与非目标

### 2.1 产品目标

- 将自然语言需求、Markdown 目录或纯文本目录转化为可执行的章节计划。
- 批量创建结构统一、命名有序的 Markdown 章节文档。
- 使用单章写作卡约束 AI 写作，使每章有明确目标、问题、材料和边界。
- 让观点、证据、引用和章节建立可追踪关系，降低事实与引用风险。
- 提供从草稿、审校、修订、质量检查到完成的显式工作流。
- 支持全书一致性检查、质量门禁、版本恢复和发布交付。

### 2.2 非目标

- 不替代通用文字处理器或完整排版软件。
- 不承诺 AI 自动生成的事实天然正确；高风险内容必须由证据与人工审核确认。
- 不在 MVP 中提供实时多人共同编辑。
- 不建设封闭的内容存储格式；正文以可迁移的 Markdown 和通用资源文件为主。
- 不把网页搜索摘要直接视为可引用证据。

## 3. 目标用户

### 3.1 核心用户

- 非虚构作者：需要把选题、目录、资料变成长篇成稿。
- 编辑与内容策划：需要控制章节目标、结构、重复度和交付进度。
- 历史、人文与研究型写作者：需要区分原始材料、后世记载和现代研究。
- 企业内容团队：需要批量生产手册、课程、行业报告或知识库文章。

### 3.2 协作角色

- 作者：规划、写作和修订章节。
- 研究员：收集、核验和关联证据。
- 编辑：执行结构、事实、语言和引用审校。
- 审批人：签核章节或全书版本。
- 发布负责人：完成备份、导出和线上发布。

## 4. 核心使用场景

1. 用户描述书稿主题、受众和目标，AI 生成初始目录；用户调整后批量创建章节文件。
2. 用户粘贴已有目录，选择按章、按节或单文件输出，并按“篇/部”建立目录层级。
3. 用户为每章填写写作目标、目标字数、核心问题、必用材料和避免重复内容，再批量生成草稿。
4. 用户导入已有 Markdown 项目，继续管理章节状态、材料、审校问题和发布流程。
5. 编辑运行全书检查，定位证据缺口、章节重复、叙事风险和格式问题，并逐项修复。
6. 团队在交付前查看质量基线、签核状态与发布阻断项，生成可发布版本。

## 5. 产品信息架构

产品分为三个一级工作区：

| 工作区 | 目的 | 主要能力 |
|---|---|---|
| 生成器 | 从需求形成文件结构 | 需求输入、目录生成/解析、目录编辑、写作卡、输出设置、批量建文档 |
| 文档工作区 | 完成单章写作 | 章节列表、状态流转、Markdown 编辑、AI 生成/重写、差异确认、图片与 Git |
| 全书管理 | 控制整本书的质量和交付 | 规划看板、知识库、证据台账、审校流水线、高级分析、质量门禁、发布状态 |

全书管理包含以下模块：

- 规划看板
- 全书知识库
- 史料与证据台账
- 审校流水线
- 高级审校：总览、全书分析、史料与引用、人物/地名/年代、智能成稿、图谱与自动化、协作签核、交付发布
- 一致性与质量门禁
- 发布状态

## 6. 核心业务流程

### 6.1 新建项目

1. 输入项目名称、内容类型、读者、目标和补充要求。
2. 选择 AI 生成目录，或直接粘贴 Markdown、编号列表、缩进列表及中文“篇/章”目录。
3. 在树形目录中重命名、删除或移动条目。
4. 选择拆分规则：按章、按节或合并为单文件。
5. 设置目标文件夹、是否按篇分目录、文件模板和 README。
6. 为章节补充写作卡。
7. 预览文件数量及路径，确认后一次性写入。
8. 将目录保存为项目，进入文档工作区。

### 6.2 章节生产

章节状态采用明确状态机：

`待写作 → 生成中 → 草稿待确认 → 待审校 → 修改待确认 → 待质量检查 → 已完成`

任意生成失败进入“生成失败”，保存人工修复后的内容可恢复为“草稿待确认”。处于“修改待确认”的章节保存后进入“待质量检查”。

单章生产步骤：

1. 读取章节标题、标题层级、写作卡、项目知识库和关联证据。
2. 生成或重写正文，但保留 frontmatter、写作卡、标题层级、引用、链接和图片。
3. 展示修改差异，由用户接受、继续修改或撤销。
4. 保存文件并推进工作流状态。

批量生产支持：

- 仅生成待写作章节。
- 重写全部章节。
- 重写所选章节。
- 展示总数、完成数和当前章节。
- 用户可立即终止；已完成结果保留，未执行项不改动。
- 提供通用非虚构、心理/成长、历史写作和自定义提示词预设。

### 6.3 证据约束写作

1. 导入或创建材料记录，保存标题、来源、摘要、原文摘录和定位信息。
2. 把材料关联到章节与具体主张。
3. 标记证据状态与强度，包括直接、间接、不充分或相互矛盾。
4. 系统计算主张覆盖率，并识别无来源、弱支持、单一来源和反证冲突。
5. AI 写作只使用当前项目中与本章相关的材料；没有证据时必须显式提示，不得虚构来源。
6. 引文需要支持回看上下文与原文核对。

### 6.4 审校与质量门禁

审校流水线包括：

1. 内容完整性校验。
2. 结构逻辑校验。
3. 事实准确性校验。
4. 专业或技术校验。
5. 语言文字校验。
6. 引用来源校验。
7. 全书一致性校验。
8. 出版格式校验。

以下问题默认阻止章节完成或全书发布：

- 正文仍含占位符。
- 字数显著低于写作卡目标。
- 存在未处理的“待核实”事实。
- 写作卡要求的必用材料未关联或未使用。
- 高优先级审校问题未关闭。
- 必须签核的角色尚未批准。

系统应提供章节质量热力图、出版准备度评分、质量基线和增量回归结果。评分用于定位风险，不替代编辑决策。

### 6.5 交付与发布

- 创建项目备份和可恢复快照。
- 查看 Git 状态，完成初始化、暂存和提交。
- 生成章节索引、附录和章节过渡段草稿。
- 校验文件、资源、链接与发布配置。
- 输出 Markdown 项目；可选生成静态阅读站点并发布到 GitHub Pages。
- 发布前再次运行全书检查，阻断项清零后才允许标记为“可发布”。

## 7. 功能需求

### 7.1 P0：独立可用闭环

| 编号 | 需求 | 验收标准 |
|---|---|---|
| P0-01 | 创建或打开项目 | 可选择本地目录；重启后可从最近项目恢复；移除记录不删除原文件 |
| P0-02 | 解析目录 | 支持 Markdown 标题、列表、缩进、编号与中文篇章格式；空行被忽略 |
| P0-03 | 编辑目录 | 支持重命名、删除、移动；删除父项时明确提示会包含子项 |
| P0-04 | 生成文件计划 | 支持按章、按节、单文件；支持按篇建目录；路径顺序稳定且文件名经过安全清洗 |
| P0-05 | 写作卡 | 每章可保存目标、目标字数、核心问题、必用材料和避免主题 |
| P0-06 | 批量写文件 | 写入前展示预览；冲突时要求覆盖确认；失败时返回具体文件和原因 |
| P0-07 | 文档编辑 | 可浏览、读取、编辑和保存 Markdown；未保存修改切换文件时需提醒 |
| P0-08 | AI 成稿 | 支持单章及批量生成；没有 API 配置时给出可操作提示；生成失败不破坏原文 |
| P0-09 | 状态管理 | 章节状态按状态机推进；列表与看板同步显示状态、字数和错误 |
| P0-10 | 基础质量检查 | 检查占位符、字数、必用材料和待核实标记，并给出文件定位 |
| P0-11 | 项目备份 | 可创建快照、查看快照列表并恢复指定快照 |
| P0-12 | 数据可迁移 | 项目正文不依赖私有数据库即可读取；辅助元数据可随项目导出 |

### 7.2 P1：专业写作与审校

- 全书知识库：统一人物、地点、术语、年代和标准名称。
- 证据台账：材料导入、摘录、锚点、主张关联、证据强度和反向索引。
- 八阶段审校流水线及问题关闭机制。
- 全书重复度、结构、叙事性、时间线和因果链分析。
- AI 修复建议与可逆文本差异。
- 章节质量热力图、出版准备度和质量回归。
- Git 集成及项目级版本记录。

### 7.3 P2：团队交付与发布

- 角色签核、评论与任务分派。
- 多端项目同步与冲突处理。
- 索引、附录、静态阅读站点与更多导出格式。
- 可配置的质量规则、内容类型模板和组织级提示词。
- 自动化任务队列和增量审校。

## 8. AI 行为规范

- AI 必须优先遵守章节写作卡与当前章节边界。
- 只引用传入的项目材料；不得虚构论文、书目、引文、页码或链接。
- 明确区分材料记载、现代研究解释和作者推断。
- 不得把搜索摘要当作已核实事实。
- 重写时保留结构性内容和不在任务范围内的原文。
- 输出正文不得包含解释性寒暄或外层 Markdown 代码围栏。
- AI 变更必须可审阅、可拒绝、可撤销。
- 涉及历史、医学、法律、财务等高风险结论时，显示人工核验提示。

## 9. 数据模型

独立产品至少维护以下领域对象：

- Project：项目名称、根目录、子目录、文件列表、创建及更新时间。
- OutlineNode：标题、层级、父子关系和排序。
- ChapterDocument：路径、标题、正文、状态、字数和错误。
- ChapterBrief：目标字数、写作目标、核心问题、必用材料、避免主题。
- KnowledgeEntry：实体类型、标准名称、别名、说明和关联章节。
- EvidenceRecord：来源、摘录、锚点、核验状态、独立性和元数据。
- Claim：章节中的主张、状态、关联证据及各证据强度。
- EditorialIssue：阶段、严重度、章节、文本位置、建议、负责人和状态。
- Approval：角色、对象、结论、意见和时间。
- Snapshot：项目版本、变更摘要、创建人和恢复信息。
- PublicationState：检查结果、阻断项、发布目标和最近发布记录。

项目正文与二进制资源保存在用户目录；最近项目、密钥和本机授权信息保存在应用数据目录。API Key 必须进入操作系统安全存储，不得写入项目文件或日志。

## 10. 独立产品边界与集成

### 10.1 可复用内核

`@next-work-dashboard/outline-scaffolder` 提供：

- 目录解析、章节文档规划、文件名清洗和 README 生成等纯 TypeScript 能力。
- 编辑分析、证据覆盖和质量评估能力。
- React 产品界面和样式。
- 宿主无关的 `OutlineScaffolderAdapter` 契约。

### 10.2 宿主能力

独立桌面壳或嵌入式宿主负责提供：

- 文件与目录授权、读取、写入、批量变更。
- AI 对话和可选图片生成。
- 密钥安全存储。
- 研究检索和外部链接打开。
- Git 操作、项目记录、备份与发布通道。

任何宿主专用 API 都不得直接进入 core 层。可选能力缺失时，对应入口应降级或隐藏，不应导致整个产品白屏。

## 11. 非功能需求

### 11.1 可靠性

- 批量写入优先使用可回滚的 mutation；中途失败必须报告已成功和未成功项。
- AI 生成前保留原文；覆盖或恢复操作必须二次确认。
- 自动保存不得覆盖外部进程刚修改的文件，检测到冲突时要求用户选择。
- 应用异常退出后可恢复最近一次编辑内容和任务状态。

### 11.2 性能

- 1,000 行以内目录解析和预览在普通桌面设备上应低于 200 ms。
- 500 个 Markdown 文件的项目扫描应在 3 秒内呈现首批结果，并显示持续进度。
- 长任务必须提供进度、当前对象、取消和失败重试。
- 大型全书分析采用增量计算，未修改章节不重复执行昂贵检查。

### 11.3 安全与隐私

- 默认本地优先，用户明确触发后才把内容发送给 AI 或检索服务。
- 调用外部服务前说明发送范围；日志不得记录密钥和完整敏感正文。
- 文件操作限制在用户授权根目录内，拒绝路径穿越。
- 外部链接由系统浏览器打开并进行协议白名单校验。

### 11.4 可访问性与易用性

- 核心流程可用键盘完成，交互元素有可识别名称和焦点状态。
- 状态与风险不能只依赖颜色表达。
- 空状态、错误状态和无配置状态必须给出下一步动作。

## 12. 成功指标

### 12.1 北极星指标

每周完成质量门禁并进入“可发布”状态的有效项目数。

### 12.2 漏斗指标

- 创建项目 → 确认目录的转化率。
- 确认目录 → 成功生成首批章节文件的转化率。
- 首批文件 → 至少一个章节完成的转化率。
- 首章完成 → 全书检查执行率。
- 全书检查 → 发布就绪率。

### 12.3 质量与效率指标

- 从新建项目到生成首批章节的中位耗时。
- AI 生成后被用户直接接受、编辑后接受和放弃的比例。
- 每章平均未关闭阻断项数量。
- 有已核验证据支持的主张覆盖率。
- 批量生成失败率、文件写入失败率和快照恢复成功率。
- 30 日项目回访率和已完成章节数。

## 13. 埋点建议

仅记录产品行为和匿名统计，不记录正文、提示词、文件路径、材料内容或密钥。

- `project_created`、`project_opened`
- `outline_parsed`、`outline_ai_generated`、`outline_confirmed`
- `scaffold_previewed`、`scaffold_written`
- `chapter_generation_started/completed/failed/cancelled`
- `chapter_state_changed`
- `audit_started/completed`
- `quality_gate_blocked/passed`
- `snapshot_created/restored`
- `publication_started/completed/failed`

## 14. MVP 验收场景

1. 用户粘贴包含“篇—章—节”的中文目录，系统正确解析层级并按章生成有序文件。
2. 用户选择按篇分目录，生成 12 个以上篇目录后，文件系统字典序与内容顺序一致。
3. 用户在确认前重命名、移动和删除目录节点，最终预览与磁盘结果一致。
4. 用户配置每章写作卡后批量生成；停止任务时，已完成章节保留，未开始章节仍为待写作。
5. AI 返回带外层代码围栏的 Markdown 时，系统去除围栏后保存，不破坏 frontmatter。
6. 重写章节时只保留结构骨架并生成新正文，用户可查看可逆差异。
7. README、404、about 等特殊 Markdown 不被误识别为章节；显式 `chapter: false` 始终生效。
8. 缺少必用材料、含占位符或字数不足的章节不能标记为完成，并显示具体原因。
9. 用户创建快照、修改多个章节后可恢复，恢复结果与快照一致。
10. 未配置 AI、检索、Git 或发布能力时，基础目录与文件功能仍可正常使用，界面不白屏。

## 15. 发布计划

### 阶段 A：独立 MVP

- 独立桌面壳与首次启动流程。
- 项目、目录、文件生成、文档编辑、AI 写作、基础门禁和备份闭环。
- 完成宿主适配器收口，移除对 Prompt Lab 内部 API 的隐式依赖。

### 阶段 B：专业版

- 知识库、证据台账、全审校流水线、全书分析、Git 与质量回归。
- 内容类型模板和组织级规则。

### 阶段 C：团队版

- 角色、任务、签核、同步与团队模板。
- 多种交付渠道和组织级治理。
