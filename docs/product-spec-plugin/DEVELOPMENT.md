# 产品说明文档生成器：开发过程

## 目标

在 `prompt-lab` 内提供一个内置插件，将界面图片、PDF/Word 需求资料和代码证据合并分析，生成可评审、可追溯、可直接交付研发与测试的 Markdown 产品说明文档。

## 方案与数据流

1. 用户添加一个或多个输入文件，也可直接粘贴代码。
2. 图片在渲染进程转成 Data URL，作为视觉模型的 `image_url` 内容发送。
3. PDF/Word 复用 `document-knowledge/parser.ts`，分别通过 PDF.js 与 Mammoth 提取分页或分章节文本。
4. 代码文件以纯文本读取，保留文件名作为证据来源；单来源最多 28,000 字符、全部文本最多 90,000 字符，超限时保留首尾并明确标注截断。
5. 提示词把材料分为图片、文档、代码三类证据，要求模型区分事实、推断、冲突和待确认项。
6. 通过现有 `electronAPI.llmChat` 主进程代理调用 OpenAI 兼容接口，避免渲染进程跨域问题。模型必须支持视觉输入才能分析图片。
7. 返回的 Markdown 在应用内预览，并支持复制或下载；API Key 不写入插件存储。

## 输出结构

生成结果包含执行摘要、背景目标、用户场景、范围、信息架构、详细功能、流程与交互、业务规则、数据模型、接口集成、权限安全、非功能需求、异常边界、指标埋点、迁移兼容、风险依赖、待确认问题和证据索引。用户可选择附加开发实施过程与 Given/When/Then 验收标准。

## 代码落点

- `src/plugins/product-spec/ProductSpecPanel.tsx`：文件输入、参数、调用状态、Markdown 预览与导出。
- `src/plugins/product-spec/generator.ts`：证据裁剪、提示词构造和下载，保持为可测试纯函数。
- `src/plugins/product-spec/types.ts`：来源与生成参数的数据契约。
- `src/plugins/built-in/index.ts`：内置插件懒加载、注册与预加载映射。
- `tests/product-spec.test.ts`：来源追溯、输出约束与截断策略测试。

## 开发阶段

1. 接入阶段：注册默认关闭的内置插件，确认插件管理器可启用。
2. 采集阶段：实现多文件选择、类型校验、解析错误隔离和来源移除。
3. 分析阶段：组装多模态请求；设置低温度以减少创造性补全；显式约束证据边界。
4. 交付阶段：Markdown 预览、复制、文件下载、取消与空状态提示。
5. 验证阶段：运行定向单测、TypeScript、ESLint 和 IPC 契约检查。

## 后续增强

- 大型仓库可接入代码索引/RAG，而不是直接上传所有源码。
- 扫描 PDF 可接入 Work Browser 已支持的 Docling/OCR 服务。
- 增加历史版本、文档差异、DOCX 导出和按章节增量重生成。
- 对视觉模型能力做运行前探测，并为纯文本模型提供忽略图片的降级路径。
