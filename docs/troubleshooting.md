# 故障排查

## 1. 基本诊断顺序

1. 记录复现步骤、错误提示和发生时间。
2. 确认问题只影响某个插件，还是整个应用。
3. 禁用最近安装或更新的用户插件。
4. 使用安全模式重新启动插件环境。
5. 在开发环境运行类型检查和测试。
6. 不要直接删除数据库或整个数据目录；先备份。

## 2. 开发环境无法启动

在 `prompt-lab` 目录确认依赖和命令：

```powershell
npm install
npm start
```

常见原因：

- Node.js 或 npm 版本不兼容。
- `node-pty` 等原生模块没有针对当前 Electron 版本构建。
- Windows 防病毒软件锁定构建产物。
- 端口或旧 Electron 进程仍被占用。

不要通过删除用户数据来解决构建问题。

## 3. 测试或类型检查失败

```powershell
npx tsc --noEmit
npm test
npm run lint
```

先处理第一个真实错误。Vite CJS API deprecation 属于警告，不等于测试失败。Windows 下 Git 的 LF/CRLF 提示通常也不是代码错误。

## 4. AI 站点无法加载或注入

- 确认网络可访问目标站点。
- 检查站点 URL、输入框选择器和提交按钮选择器。
- 等页面加载完成后再注入。
- 如果站点改版，重新通过开发者工具确认选择器。
- 自动提交失败时先关闭自动提交，验证文本是否能够写入。

## 5. 文件无法打开

- 确认对应插件已启用。
- 检查文件扩展名是否已注册到 `fileEditors`。
- 如果统一“打开文件”没有完成加载，进入对应插件使用其内部打开按钮。
- 检查文件是否损坏、过大或使用了暂不支持的格式。
- Electron 文件选择 API 在普通浏览器环境不可用。

## 6. 终端无法启动

- 确认系统 Shell 路径存在。
- 检查工作区路径是否有效。
- Windows 原生模块构建失败时查看[终端功能文档](./terminal-features.md#已知问题)。
- 关闭残留终端会话后重新打开。

## 7. 插件导入失败

检查 `.nwd` 是否满足：

- 小于 2 MB。
- JSON 格式有效，`format` 为 `nwd-v1`。
- `runtime` 为 `sandbox`。
- `apiVersion` 为 `1`。
- ID、名称和语义版本合法。
- `permissions` 只包含已知权限。
- `script` 为非空字符串。

完整格式见[插件开发指南](./plugin-architecture.md#10-sandbox-插件开发指南)。

## 8. 插件提示权限不足

权限必须同时满足：

1. manifest 已声明该权限。
2. 用户在“设置 → 插件”中授予该权限。

如果更新版本新增权限，重新检查权限设置。不要通过给插件授予全部权限来绕过具体错误。

## 9. 插件被自动禁用

用户插件连续发生 3 次运行错误会触发熔断。处理步骤：

1. 查看插件卡片日志。
2. 回滚到上一个可用版本，或修复脚本后重新导入。
3. 如果界面不稳定，先启用安全模式。
4. 确认不再报错后再恢复插件。

## 10. 数据异常

- 先退出应用并备份数据，再进行任何恢复操作。
- 不要手工修改 `plugin-platform-state-v1`，除非已经备份且了解数据结构。
- 插件数据按 ID 分区；修改插件 ID 不会自动迁移旧数据。
- 数据迁移、完整导出和 SQLite 插件存储仍在开发。

## 11. 提交问题时应提供

- 应用版本和操作系统。
- 安装版或开发版。
- 完整复现步骤。
- 预期结果和实际结果。
- 错误文本、插件日志或截图。
- 是否在安全模式下仍可复现。
- 是否与某个工作区或文件有关。

提交前移除 API 密钥、令牌、个人路径、提示词内容和其他敏感数据。
