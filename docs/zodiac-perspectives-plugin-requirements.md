# 十二星座视角插件需求文档

## 1. 产品概述

“十二星座视角”是 Next Work Dashboard 的内置 AI 插件。用户输入同一个问题后，插件以十二种具有明显差异的星座角色视角分别理解问题、指出关注点并给出建议，帮助用户发现自己可能忽略的立场、风险和行动路径。

本产品定位为娱乐化的多视角思考工具。星座仅作为易理解、易记忆的角色原型和表达框架，不用于人格诊断、命运预测，也不声称输出具有科学心理测量效力。

暂定插件信息：

| 项目 | 内容 |
|---|---|
| 中文名 | 十二星座视角 |
| 英文名 | Zodiac Perspectives |
| 插件 ID | `zodiac-perspectives` |
| 类型 | 内置 AI 工具插件 |
| 图标 | ♈ |
| 默认状态 | 启用 |

## 2. 产品目标

### 2.1 核心目标

- 让用户只输入一次问题，就能获得十二种有区分度、可比较的理解方式。
- 每种视角不仅改变语气，还要改变关注点、推理路径、风险判断和行动建议。
- 将十二份回答进一步归纳为共识、分歧、盲点和推荐行动，避免信息过载。
- 支持从任一星座视角继续追问，形成可连续使用的思考流程。

### 2.2 成功指标

- 90% 以上的有效请求能够完成十二个视角的结构化输出。
- 首屏在生成开始后 2 秒内出现明确的运行反馈；支持逐项展示时，优先展示已完成视角。
- 用户能在 3 次操作以内完成“输入问题 → 生成 → 查看任一星座详情”。
- 同一轮结果中，任意两个星座的“核心关注点”不应完全相同。
- 用户可以复制单个视角、复制汇总或重新生成，无需重新输入原问题。

## 3. 目标用户与使用场景

### 3.1 目标用户

- 希望从不同角度分析工作、关系、选择和创意问题的普通用户。
- 喜欢星座文化，希望获得轻松、有参与感内容的用户。
- 需要为文案、角色、讨论或团队活动寻找多种观点的内容创作者。

### 3.2 典型场景

- 决策：是否接受一份高薪但需要异地工作的岗位？
- 沟通：应该怎样向同事指出一个反复出现的问题？
- 关系：朋友很久不回复消息，应该如何理解和处理？
- 创意：这款新产品的宣传主题可以怎样设计？
- 复盘：为什么这次项目推进不顺利？
- 娱乐：十二星座会怎样理解“稳定比热爱更重要吗”？

## 4. 产品原则

1. **差异来自思考框架，不只是文风。** 每个角色必须有不同的关注重点、判断依据和建议。
2. **先回答问题，再体现星座特色。** 不输出与问题无关的星座段子。
3. **差异清晰但不刻板冒犯。** 避免“某星座一定自私、冲动、花心”等绝对化标签。
4. **娱乐表达，实用落点。** 每个视角都必须给出可执行建议。
5. **信息透明。** 明确告知内容由 AI 生成，星座角色仅用于多视角启发。
6. **高风险问题降级处理。** 医疗、法律、投资、安全等问题不得以星座视角替代专业意见。

## 5. 核心用户流程

1. 用户打开插件，看到问题输入框和示例问题。
2. 用户输入问题，可选场景、回答长度和整体语气。
3. 用户点击“让十二星座回答”。
4. 插件校验输入并调用当前工作台已配置的 AI 服务。
5. 页面显示生成进度，并逐步呈现十二张星座卡片。
6. 用户可按星座顺序浏览，或切换到“对比总结”查看共识、分歧和建议。
7. 用户可复制单个回答、复制全部、收藏本轮、重新生成或选择某个星座继续追问。
8. 历史记录保存在本地，用户可重新打开、重命名或删除。

## 6. 功能需求

### 6.1 问题输入

- 支持 1～2000 个字符的纯文本问题。
- 支持多行输入、粘贴、清空和快捷提交。
- 空输入不得发起请求，并显示可理解的校验信息。
- 提供不少于 6 个示例问题，覆盖工作、关系、决策和创意场景。
- 默认不采集出生日期、姓名、位置等个人资料。

### 6.2 生成选项

| 选项 | 值 | 默认值 |
|---|---|---|
| 场景 | 通用、工作、关系、决策、创意、娱乐 | 通用 |
| 篇幅 | 简短、标准、深入 | 标准 |
| 语气 | 理性、温和、犀利、幽默 | 温和 |
| 汇总 | 开启、关闭 | 开启 |

选项只调整内容组织与表达，不改变安全规则。MVP 不要求用户输入自己的星座；后续可增加“优先展示我的星座”。

### 6.3 十二星座视角模型

每个星座角色由“核心驱动力、首要关注、常见提问方式、建议倾向、表达风格”共同定义。以下为内容设计基线，不是对现实个体的断言。

| 星座 | 视角关键词 | 首要关注 |
|---|---|---|
| 白羊座 | 直接、行动、突破 | 现在能做什么，怎样快速验证 |
| 金牛座 | 稳定、价值、耐久 | 成本收益、资源和长期可靠性 |
| 双子座 | 信息、变化、连接 | 是否存在其他解释和沟通路径 |
| 巨蟹座 | 感受、安全、照顾 | 对关系、归属感和情绪的影响 |
| 狮子座 | 自信、创造、影响 | 主导权、表达效果和个人价值 |
| 处女座 | 细节、秩序、改进 | 漏洞、步骤、标准和可优化处 |
| 天秤座 | 平衡、公平、协商 | 各方立场、关系成本和折中方案 |
| 天蝎座 | 深度、动机、边界 | 隐藏动机、信任、风险和底线 |
| 射手座 | 可能、成长、远方 | 长期意义、自由度和新机会 |
| 摩羯座 | 目标、责任、执行 | 现实约束、计划、责任和结果 |
| 水瓶座 | 独立、系统、创新 | 规则是否合理及非传统解法 |
| 双鱼座 | 共情、想象、融合 | 未表达的感受、愿景和温柔解法 |

生成时必须同时满足：

- 十二个星座全部出现且每个仅出现一次。
- 各视角忠实回应原问题，不擅自补充关键事实。
- 每个视角至少包含“如何理解”“最关注什么”“建议怎么做”。
- 标准篇幅下，每个视角建议控制在 80～160 个汉字。
- 不把太阳星座描述为决定人格或行为的事实。

### 6.4 结果展示

结果页包含三个区域：

1. **本轮问题**：展示原问题、选项、生成时间和重新生成入口。
2. **十二视角**：以 12 张卡片展示星座名称、关键词、核心理解、关注点和行动建议。
3. **对比总结**：展示共同结论、主要分歧、容易忽略的盲点和综合行动建议。

交互要求：

- 默认按黄道十二宫顺序排列。
- 支持卡片网格与单列阅读两种布局；窄窗口自动切换为单列。
- 支持“只看差异”模式，突出各卡片相对于共识的独特观点。
- 单卡支持复制、展开/收起和“以此视角追问”。
- 全局支持复制全部、复制总结、重新生成和新建问题。
- 正在生成、部分成功、失败和取消均有明确状态。

### 6.5 对比总结

启用汇总时，系统必须输出：

- 3～5 条跨视角共识。
- 2～4 组有代表性的分歧，以及产生分歧的关注点。
- 1～3 个原问题可能忽略的盲点。
- 一份不依赖星座标签的综合行动建议，优先给出下一步。

汇总不得简单重复十二张卡片，也不得用投票数量宣称某个答案客观正确。

### 6.6 追问

- 用户可选择一个星座进入追问模式。
- 追问保留原问题、本轮回答和所选视角上下文。
- 页面必须持续显示当前采用的星座视角，并提供“退出该视角”。
- 追问回答仍须遵守事实准确性与高风险内容规则。
- MVP 支持单视角追问；多星座辩论列入后续版本。

### 6.7 历史与收藏

- 自动保存最近 50 轮生成记录到本地。
- 记录内容包括问题、生成选项、十二视角、汇总、时间和收藏状态。
- 支持搜索问题文本、收藏/取消收藏、重命名和单条删除。
- 支持一键清空非收藏记录，执行前需二次确认。
- 不保存 AI 服务密钥；密钥继续由工作台统一管理。

### 6.8 分享与导出

- 支持复制单个视角、全部视角和对比总结为 Markdown。
- 复制内容必须包含原问题、生成时间和“AI 生成的娱乐化多视角内容”说明。
- MVP 不生成公开分享链接，不自动发布到外部平台。

## 7. AI 输出契约

AI 层应优先返回可校验的结构化 JSON，界面不得依赖 Markdown 标题解析。建议数据结构如下：

```ts
interface ZodiacPerspectiveResult {
  question: string;
  perspectives: Array<{
    sign: 'aries' | 'taurus' | 'gemini' | 'cancer' | 'leo' | 'virgo'
      | 'libra' | 'scorpio' | 'sagittarius' | 'capricorn' | 'aquarius' | 'pisces';
    interpretation: string;
    focus: string[];
    advice: string[];
    caution?: string;
  }>;
  synthesis?: {
    consensus: string[];
    disagreements: Array<{ topic: string; positions: string[] }>;
    blindSpots: string[];
    nextSteps: string[];
  };
}
```

输出校验规则：

- `perspectives` 必须正好包含 12 项，且 `sign` 不重复。
- 所有面向用户的字符串去除不可见控制字符并限制长度。
- JSON 解析失败时允许自动修复或重试 1 次。
- 仍失败时显示错误和“重新生成”入口，不展示半解析的乱码内容。
- 若只有部分星座生成失败，可保留成功项并允许只重试缺失项。

## 8. AI 提示策略

系统提示应包含以下约束：

- 将十二星座视为十二种虚构的思考原型，而非真实人格判断。
- 对同一事实保持一致，不为制造差异而编造背景。
- 差异必须体现在关注点、论证和行动建议，不能只替换形容词。
- 避免贬损、宿命论、恐吓和绝对化表达。
- 遇到信息不足时明确说明假设，并提出需要补充的问题。
- 对医疗、法律、财务、人身安全等高风险问题提供一般信息和求助建议，不以角色口吻给出确定性专业结论。
- 严格按约定 JSON Schema 输出。

## 9. 状态与异常处理

| 场景 | 产品行为 |
|---|---|
| 未配置 AI 服务 | 显示配置引导，不清空用户输入 |
| 请求超时 | 保留问题和选项，允许重试 |
| 用户取消 | 停止后续生成，保留已完成内容并标记未完成 |
| 输出缺少星座 | 标记缺失项，并提供“补全缺失视角” |
| 内容被安全策略拒绝 | 说明无法按原方式回答，并给出安全改写建议 |
| 网络中断 | 显示离线状态；历史记录仍可查看 |
| 本地存储达到上限 | 优先提示清理旧的非收藏记录，不静默覆盖收藏内容 |

## 10. 安全、隐私与内容边界

- 用户输入仅发送给当前工作台选定的 AI 服务；页面应沿用工作台已有的服务与隐私提示。
- 插件不请求文件、剪贴板、位置、联系人等与核心功能无关的权限。
- 不根据星座对招聘、信贷、教育、医疗等高影响事项作决定或排名。
- 不输出针对某一星座群体的仇恨、侮辱或确定性负面归因。
- 涉及自伤、暴力、违法或紧急健康风险时，优先执行平台安全流程，不维持娱乐化角色扮演。
- 历史记录默认仅存本机，用户可删除；不得包含 AI 密钥和认证令牌。

## 11. 非功能需求

- 支持工作台亮色与暗色主题。
- 在 1024×640 及以上窗口完整可用；较窄布局无横向溢出。
- 所有按钮支持键盘操作并具备可见焦点；星座图标不得作为唯一信息载体。
- 动态进度应通过可访问状态文本传达，不能只依赖颜色和动画。
- 单次生成期间防止重复提交；取消和重试行为幂等。
- 历史记录读取不依赖网络，50 轮数据下列表操作无明显卡顿。
- 用户输入与 AI 输出均按纯文本安全渲染；如支持 Markdown，必须经过可信清洗。

## 12. MVP 范围

### 12.1 必须包含

- 问题输入与基础生成选项。
- 十二星座结构化回答。
- 卡片浏览与对比总结。
- 单卡、全部和总结复制。
- 单星座追问。
- 最近 50 轮本地历史与收藏。
- 加载、取消、重试、缺失项补全和未配置 AI 的异常状态。
- 娱乐化定位、安全提示、亮暗主题与基础无障碍支持。

### 12.2 暂不包含

- 出生星盘、上升星座、月亮星座或出生时间计算。
- 每日/每周运势、合盘、占卜或未来事件预测。
- 社交账号、公开社区、排行榜和公开分享链接。
- 语音输入、语音播报和图片生成。
- 多星座实时辩论、多人协作和云端历史同步。
- 自建模型训练或基于用户行为推断真实人格。

## 13. 后续版本候选

- 双星座对谈：选择两个视角围绕分歧进行三轮讨论。
- 十二星座会议：由“主持人”归纳各方方案并形成决策纪要。
- 自定义角色原型：用户调整某一视角的关注权重，但仍保留安全边界。
- 结果可视化：以“行动速度、风险偏好、关系关注、长期导向”等维度展示观点分布。
- 模板库：提供面试、团队复盘、关系沟通、产品评审等问题模板。
- 经用户明确选择后，将结果保存到工作台知识库。

## 14. 验收标准

### 14.1 主流程

- 给定一个有效问题，点击生成后能得到且只得到十二个不重复星座视角。
- 每个视角均包含理解、关注点和至少一条行动建议。
- 开启汇总后，结果包含共识、分歧、盲点和下一步建议。
- 用户可复制任一视角及完整结果，复制文本与页面内容一致。
- 用户可从任一卡片发起追问，并能明确退出该视角。

### 14.2 差异质量

- 使用固定测试问题“我是否应该离开稳定但没有成长的工作？”时：
  - 白羊视角包含近期行动或小步验证；
  - 金牛视角包含财务或稳定性评估；
  - 巨蟹视角包含情绪或家庭影响；
  - 天秤视角包含多方权衡；
  - 天蝎视角包含真实动机或底线；
  - 摩羯视角包含计划、责任或时间表；
  - 水瓶视角包含非传统替代方案；
  - 其余视角符合第 6.3 节定义。
- 十二份回答不得出现大段相同文本，不能仅替换星座名称。

### 14.3 异常与安全

- 空问题、超长问题、超时、断网、取消和无 AI 配置均有可恢复提示。
- AI 返回非法 JSON 或缺少星座时，系统会重试或提供补全入口。
- 医疗、法律、财务等高风险测试问题会显示适当提示，不把星座建议包装成专业结论。
- 重启应用后可查看已保存历史，删除记录后不再出现。

## 15. 待确认事项

以下项目不阻塞 MVP 需求评审，但应在视觉设计或开发开始前确认：

1. 插件最终中文名采用“十二星座视角”“星座圆桌”还是其他品牌名。
2. 首版生成采用一次请求返回完整 JSON，还是拆分请求并行生成；产品更偏好支持渐进展示的方案。
3. 是否复用 AI 对话模块的模型选择器，或仅使用工作台当前默认模型。
4. 历史记录使用插件私有数据存储还是工作台现有会话存储。
5. 是否将“只看差异”纳入 MVP；若开发成本较高，可降级为首版后的增强项。
