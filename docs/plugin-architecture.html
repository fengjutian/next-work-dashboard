插件架构设计文档

1. 概述

插件系统采用双层架构：内核 React 插件 + 用户沙箱插件，统一通过 PluginRegistry（全局单例）管理生命周期。ActivityBar 渲染所有已启用插件的图标按钮，点击后主内容区渲染对应面板。

用户操作 → ActivityBar → PluginRegistry.getEnabled()
                            │
            ┌───────────────┼───────────────┐
            ▼               ▼               ▼
       内置 Plugin      用户 Plugin     用户 Plugin
       (React 组件)     (旧版 Markdown)  (新版 iframe)
                            │               │
                            └───────┬───────┘
                                    ▼
                            DynamicPlugin
                                    │
                            PluginSandbox (iframe)
                                    │
                            postMessage ◄──► usePluginBridge

2. 内核插件层（Plugin 接口）

接口定义

// src/plugins/types.ts
interface Plugin {
  id: string;                                    // 唯一标识
  name: string;                                  // 显示名
  icon: ComponentType<{ className?: string }>;   // 图标组件
  component: FC;                                 // 主面板 React 组件
  enabled: boolean;                              // 启用/禁用
  order: number;                                 // 排序权重
}

PluginRegistry API

方法说明
register(plugin)注册插件，id 重复则覆盖
registerAll(plugins)批量注册
unregister(id)卸载插件
get(id)获取单个插件
getAll()按 order 排序返回全部
getEnabled()返回已启用的插件
setEnabled(id, enabled)切换启用状态
subscribe(fn)订阅变更，返回取消函数

3. 用户沙箱插件层

用户编写的 JavaScript 脚本运行在隔离 iframe 中，通过 postMessage 与 Host 通信。

架构图

┌──────────────────────────────────────────┐
│  Host (React Renderer)                   │
│  usePluginBridge                         │
│  ├─ store    → 读取 Zustand 状态快照      │
│  ├─ actions  → 剪贴板 / 注入 / 打开URL    │
│  ├─ data     → localStorage 私有存储      │
│  ├─ ui       → Toast / 主题令牌 / 容器    │
│  ├─ preview  → Markdown / 图片 / PDF      │
│  └─ file     → Electron 文件对话框        │
│         ▲                                │
│         │ postMessage                    │
│         ▼                                │
│  ┌──────────────────────────────────┐    │
│  │ iframe (sandbox="allow-scripts") │    │
│  │ CSP: default-src 'none'          │    │
│  │ <script> SDK 运行时 </script>    │    │
│  │ <script> 用户脚本  </script>     │    │
│  └──────────────────────────────────┘    │
└──────────────────────────────────────────┘

postMessage 协议

interface SandboxMessage {
  requestId: string;   // UUID，响应时原样返回
  channel: 'store' | 'ui' | 'actions' | 'data' | 'preview' | 'file';
  method: string;      // 方法名
  args?: unknown[];    // 参数数组
  ok?: boolean;        // 响应：是否成功
  result?: unknown;    // 响应：返回值
  error?: string;      // 响应：错误信息
  event?: string;      // 事件名
  payload?: unknown;   // 事件数据
}

权限对应能力

SDK API 参考

// ── store ──
await PluginSDK.store.getPrompts()
await PluginSDK.store.getSites()
await PluginSDK.store.getTabs()
await PluginSDK.store.getActiveTab()
PluginSDK.store.subscribe('prompts-changed', fn)

// ── ui ──
await PluginSDK.ui.setContent('<h1>Hello</h1>')
await PluginSDK.ui.showToast('操作成功', 'success')

// ── actions ──
await PluginSDK.actions.injectPrompt('deepseek', '你好', true)
await PluginSDK.actions.copyToClipboard('text')
await PluginSDK.actions.openUrl('https://...')

// ── data (私有存储) ──
await PluginSDK.data.set('key', { foo: 'bar' })
await PluginSDK.data.get('key')

// ── preview ──
await PluginSDK.preview.markdown('# 标题')
await PluginSDK.preview.code('const x = 1;', 'javascript')

// ── file ──
await PluginSDK.file.pickOpen({ accept: '.json' })
await PluginSDK.file.pickSave(data, 'export.json')

5. 设计要点

  1. 安全隔离 — iframe sandbox="allow-scripts" + CSP default-src 'none'
  2. 权限最小化 — 每个 API 调用前校验 permissions 数组
  3. 私有存储隔离 — localStorage key 前缀 pksdk:data:<pluginId>
  4. 向后兼容 — 同时支持旧版 Markdown content 和新版 script 沙箱
  5. 响应式注册 — subscribe() 支持 React 组件重渲染
  6. 事件推送 — Host 可主动推送状态变更事件到 iframe
