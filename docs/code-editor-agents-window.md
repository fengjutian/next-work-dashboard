# 代码编辑器 Agents Window 功能设计

## 1. 文档状态

- 状态：阶段 A 首版已实现
- 创建日期：2026-08-04
- 适用模块：`prompt-lab/src/plugins/code-editor`
- 参考产品：Visual Studio Code Agents Window（Preview）

本文定义 next-work-dashboard 代码编辑器中的 Agents Window。目标是借鉴“以 Agent 会话为中心”的工作方式，并复用项目现有 AI 编辑、Diff 审阅、工作区、终端与 Git 能力；不复制或依赖 VS Code 的私有实现。

## 2. 背景与目标

当前代码编辑器已经支持：

- 当前文件和多文件 AI 修改；
- 工作区级 AI 对话持久化；
- Token 预算、请求中断恢复；
- 修改候选 Diff、接受、拒绝和撤销；
- 工作区终端、任务与 Git 操作。

现有入口位于底部“AI 修改”页签，更适合一次性修改，不适合浏览和管理多个 Agent 任务。Agents Window 将提供独立、可切换的 Agent 工作界面，让用户从“编辑文件”切换到“管理任务”。

首版目标：

1. 在代码编辑模块工具栏提供“Agents”入口。
2. 使用独立视图展示会话列表、对话/任务输入和修改候选。
3. 允许创建、选择、重命名和归档本地 Agent 会话。
4. 会话绑定当前工作区，切换工作区时只显示对应会话。
5. 复用现有 AI 生成及 Diff 审阅链路，不自动写入文件。
6. 明确展示运行状态、待审修改数量和最近活动时间。

## 3. 非目标

首版不包含：

- GitHub Copilot、Claude CLI 或 VS Code 官方会话同步；
- 多 Agent 真正并行执行；
- Git worktree、容器或远程沙箱隔离；
- 后台进程在应用退出后继续运行；
- 自动提交、自动推送或自动创建 Pull Request；
- 与 VS Code Agents Window 完全一致的 UI 或协议。

这些能力需要独立的执行器、任务队列和隔离策略，列入后续阶段。

## 4. 用户流程

### 4.1 打开 Agents Window

用户在代码编辑器工具栏选择“Agents”。如果尚未打开工作区，界面提示先打开文件夹；不会创建无工作区的代码修改会话。

### 4.2 创建任务

1. 用户点击“新建会话”。
2. 系统创建绑定当前工作区的本地会话。
3. 用户输入任务，并选择当前文件或多文件模式。
4. 系统调用现有 AI 编辑生成器。
5. 生成结果进入待审区，不自动保存。

### 4.3 审阅变更

用户从 Changes 区域打开候选文件，进入现有 Diff Editor，然后选择接受、部分接受或拒绝。接受后的修改仍保持未保存状态，继续遵循代码编辑器的保存和外部冲突规则。

## 5. 界面结构

```text
┌ 工具栏：Explorer / 文件 / 搜索                    Agents ┐
├────────────────┬──────────────────────────┬──────────────┤
│ Sessions       │ Agent conversation       │ Changes      │
│ + 新建会话      │ 状态 / 工作区 / 模式       │ 待审文件       │
│ 当前会话        │ 消息记录                  │ 已接受统计      │
│ 最近会话        │ 任务输入与运行按钮          │ 打开 Diff       │
│ 已归档          │                          │              │
├────────────────┴──────────────────────────┴──────────────┤
│ 状态栏                                                   │
└─────────────────────────────────────────────────────────┘
```

窄窗口下 Changes 列可折叠到对话区下方。界面颜色和间距使用项目现有设计令牌，不硬编码 VS Code 配色。

## 6. 数据模型

```ts
type AgentSessionStatus = 'idle' | 'running' | 'review' | 'completed' | 'interrupted';

interface AgentSession {
  id: string;
  workspacePath: string;
  workspaceName: string;
  title: string;
  status: AgentSessionStatus;
  createdAt: number;
  updatedAt: number;
  archivedAt?: number;
  filesChanged: number;
  accepted: number;
}

interface AgentConversation {
  sessionId: string;
  messages: AiConversationMessage[];
  draft: string;
}
```

首版使用渲染进程本地存储，键名必须带版本号。文件内容候选继续复用当前 `AiFileProposal`，不重复建立另一套 Diff 模型。

## 7. 状态与安全规则

- Agent 只能访问当前已授权工作区内的文件。
- AI 结果只生成候选；未经用户接受，不修改编辑器文档或磁盘。
- 接受多文件修改时继续使用现有工作区事务，避免部分写入。
- 切换会话不能丢失输入草稿、消息或待审候选。
- 运行中的会话禁止重复提交；用户可以等待本次请求完成。
- API Key 继续由现有安全存储管理，不写入 Agent 会话数据。
- 会话标题、消息和文件路径属于本地数据，首版不上传到额外服务。

## 8. 分阶段计划

### 阶段 A：本地 Agents 视图（本次）

- 工具栏 Agents 开关；
- 三栏独立视图；
- 当前工作区的本地会话列表；
- 新建、选择、重命名、归档会话；
- 复用现有 AI 输入、生成、消息和候选 Diff；
- 会话数据持久化；
- 基础单元测试、类型检查和 lint。

限制：同一工作区只有当前选中会话可以执行；执行仍运行在现有渲染进程调用链中。

实现记录（2026-08-04）：已加入工具栏入口、三栏 Agents 视图，以及按工作区过滤的会话创建、搜索、置顶、分叉、重命名、归档、恢复和删除。分叉复制对话上下文及验证配置，但不复制待审修改和中断请求。会话拥有隔离的对话、日志与候选持久化，Changes 可进入 Diff Editor 审阅，并显示新增、修改、删除、重命名与增删行统计，支持直接接受/拒绝单文件和确认后批量处理。每个会话可配置有序验证流水线、手动运行或在接受修改后自动运行；任务串行执行且失败即停，输出、最终状态、退出码和耗时写入会话日志，并支持取消。验证失败后可将最近日志一键整理为继续修复指令。模型流式响应指标以最多每 100ms 一次的频率更新，展示接收字符数、首字节时间和总耗时，并写入会话日志；多文件 JSON 仍只展示指标，不渲染未完成内容。首次运行会根据任务首行生成会话标题；会话记录修改文件数、接受数量和完成状态。永久删除会同步清理本地对话、日志、中断请求和候选草稿。Agent 请求已支持取消、已中断状态和重新运行；运行期间会锁定其他会话，防止结果写入错误会话。真正并行执行和 worktree 隔离仍属于阶段 B/C。

### 阶段 B：任务执行器

- 将 Agent 调用迁移到独立任务服务；
- 支持任务队列、并发上限和细粒度进度事件；
- 应用重启后的任务恢复；
- 每个会话独立候选集和输出日志。

### 阶段 C：隔离与交付

- Git worktree 隔离；
- 在会话内运行测试和构建任务；
- 合并、提交和创建 Pull Request；
- 可选接入外部 Agent 提供方。

实现进度（2026-08-04）：已完成主进程 worktree 服务、IPC 与会话状态 UI，支持安全创建、查询、合并和确认后放弃。worktree 位于应用数据目录，目标路径和分支由受校验的会话 ID 确定。启用后，AI 从 worktree 读取上下文和活动文件，审阅后的候选通过工作区事务原子写入 worktree，验证流水线也以 worktree 为根目录；主工作区文件和编辑器内存不会被候选接受操作修改。为避免删除/重命名等操作出现跨根目录歧义，隔离模式只允许批量原子接受，单文件和 Hunk 接受会被阻止。合并前要求主工作区干净，并比较共同基线以来的路径变更；重叠修改会被阻止。通过预检后生成 squash 提交，意外冲突自动回滚合并状态，成功后清理 Agent worktree 与临时分支。

任务执行进度（2026-08-04）：代码分析、文件修改、会话摘要和内联修改的模型请求已接入主进程 `AgentTaskService`，支持并发上限、同 worktree 写锁、取消、重试、任务事件及真实队列统计。Agent 数据启动时从 `localStorage` 一次性迁移到 SQLite，并从数据库恢复会话、日志、消息和候选；本地存储暂时保留为兼容回退。任务快照会移除 API Key。隔离 worktree 可从界面推送分支并创建 GitHub Pull Request，Token 只用于当次 IPC 请求。真正允许用户同时操作多个会话、应用重启后接管运行中任务、可视化解决 Agent 合并冲突，以及容器/SSH 执行环境仍未完成。

作用范围（2026-08-04）：Agents 输入区支持“工作区、选中目录、选中文件”三种范围，Explorer 文件和目录右键菜单可直接“在 Agents 中打开”。目录和文件范围自动使用多文件上下文；分析与修改均受范围约束，生成结果无法在所选目录或文件集合之外创建、修改、删除或重命名文件。

## 9. 验收标准

阶段 A 完成时应满足：

1. 打开工作区后可以从工具栏进入和退出 Agents 视图。
2. 可以新建至少两个会话，并在刷新或重启后恢复会话元数据。
3. 会话只出现在其绑定的工作区中。
4. 可以重命名和归档非运行中的会话。
5. 输入任务后可调用现有单文件或多文件 AI 修改。
6. 生成的文件候选可从 Changes 区打开现有 Diff 审阅。
7. 未配置 AI API、未打开文件和请求失败时有明确提示。
8. Agents 视图不会绕过现有保存确认、路径校验或工作区事务。
9. `npm run typecheck`、相关测试与 lint 通过。

## 10. 已知风险

- 当前 AI 状态按工作区保存，迁移为按会话保存时需要兼容旧数据。
- 大型候选内容存储在 `localStorage` 可能达到容量上限；阶段 B 应迁移到 SQLite。
- 渲染进程执行长请求时，取消与并发控制能力有限。
- 多会话共享未保存编辑器文档时，候选可能过期；必须继续执行现有版本检查。
